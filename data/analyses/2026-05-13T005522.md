# Session 2026-05-13T005522 — rev protocol (engine running), 3-device rig

**Purpose:** run #2 of the coordinated test plan. `scripts/guided_session.py`
rev protocol (idle / throttle blips to ~2k/3k/4k / a ~12 s hold at ~2.5k /
engine off) with the Canable sniffing and the ELM327 polling Mode 01. NT510
plugged into the splitter but parked on its main menu (no traffic).

## Hardware / state

- Canable (knockoff CAN-FD, CANable2 slcan firmware) — `/dev/ttyACM0`, 500 kbps
  classic CAN, normal-mode open (ACKs only; recorder never transmits).
- ELM327 (CH340 clone, `ELM327 v1.5`) — `/dev/ttyUSB0` @ 38400, MS/HS on **HS**,
  `usbipd --auto-attach`.
- NT510 — on the splitter, main menu, idle.
- Engine **already running** at the start (warm-ish, coolant ~60 °C). Manual
  trans in neutral, parking brake on. Engine killed at the end (key left on).

## Tag correction

The rev protocol assumes you start engine-off and crank during the session, but
the engine was already running, so the operator tapped through the first three
steps while idling. In `tags.jsonl` the first three tags were originally
`key_on_engine_off`, `engine_start`, `idle_cold` — all recorded at ~750 RPM,
coolant ~60 °C. **Relabeled all three to `idle_warm`** to match reality (the
whole pre-blip stretch was just warm idle). The final `engine_off_key_on` tag is
genuine (engine actually killed there; RPM → 0 captured). Future runs: either
start from engine-off, or skip those two protocol steps.

## What was captured

`data/sessions/2026-05-13T005522/` (gitignored). ~258.6 s. CAN: **281,074 frames,
0 parse errors, 0 reconnects** — Canable solid the whole time. OBD: ~140 s of
engine-running readings (RPM/MAF/throttle/timing/load/coolant/voltage @ ~2.5 Hz),
**RPM 0–4600, MAF 1.2–66 g/s, THROTTLE 0–56 %, coolant 60→70 °C**. ~8 s after the
engine was killed the ELM327 stopped getting readings (engine off → ECM stops
answering); the supervised OBD thread caught it via the staleness heartbeat,
tore down, and retried ("did not connect", engine off) until the recorder was
stopped — expected, no protocol data lost, CAN unaffected. (Lesson confirmed: an
engine-off ELM327 just won't connect; don't kill the engine before stopping the
recorder if you want OBD through the tail.)

## Byte-vs-tag differential — candidate signals

`tools/broadcast_signals.py` over the 18 tag windows. Strongest RPM-correlated
broadcast bytes (per-window means rise monotonically with the 2k→3k→4k blips and
drop at engine-off):

| ID:byte | idle | ~2k | ~3k | ~4k | engine-off | note |
|---|---|---|---|---|---|---|
| 0x1F9:2 | ~23 | ~44 | ~66 | ~73 | ~3 | rises with RPM; ~0 off — strong RPM candidate |
| 0x23D:1 | 0 | ~19 | ~40 | ~62 | 0 | 0 at idle/off, scales with RPM — RPM-over-idle / load proxy |
| 0x29E:7 | ~117 | ~130 | ~151 | ~181 | ~117 | monotonic with RPM |
| 0x284:6 / 0x285:6 | ~125 | — | ~190 | ~188 | ~110 | jumps with throttle/RPM (0x284 and 0x285 mirror each other) |
| 0x23D:6 | ~252–255 | dips to ~28–135 *during blip onset only* | back to 255 | | ~31 | throttle-transient / pedal-rate-ish |

Engine running-vs-off flags (constant while running, flip only at `engine_off_key_on`):
0x231:0/3 (211→246), 0x284:7 / 0x285:7 (~130→244), 0x35D:0 (192→64), 0x358:1
(64→0), 0x5C5:0 (68→132), 0x590:4 (1.8→96), 0x551:3 (128→21). Useful for an
engine-state feature and for confirming the `*_engine_off` sentinels noted
elsewhere in the bindings.
