# Session 2026-05-16T223328 — NT510 passive sniff: injector PW + DID name map

**Purpose:** name the Mode 22 DIDs discovered in session 2026-05-16T214006
by passively sniffing the Foxwell NT510's diagnostic exchange with the ECM
while it streamed Engine Live Data, then pinning **injector pulse width**
(the Phase 4.E.4 fuel-surface enabler) via a throttle-blip signature.

## Method

- NT510 plugged into the OBD-II port running Engine Live Data; Canable on
  the same bus recording **broadcast-only** (`record.py`, listen mode, never
  transmits). One active tester + one passive recorder = no contention
  (the proven prior NT510-session method). Our `0xC0` poller was **not**
  run (would contend).
- The NT510 reads the ECM over `0x7E0 → 0x7E8` (same addressing as our
  Mode 22) — 2708 paired req/resp captured. We decode that ISO-TP exchange
  offline: which DID it requests for each named parameter, and the
  response values.
- Identification = NT510's named value + the DID's 4-state values
  (KOEO/cold/warm/rev from 2026-05-16T214006) + blip dynamics, cross-checked
  against independent **broadcast RPM** (`0x1F9`) for timing. No reliance on
  scaling guesses.

**Finding that corrected a wrong assumption:** the NT510 "Graph" view does
**not** narrow/raise its poll rate — it polls its whole list continuously
regardless of list-vs-graph (0x1208 and 0x1206 had near-identical request
counts, 592/590). So DID identification must be signature-driven, not
request-frequency-driven. The injector-PW lock below used the signature
method and is unaffected.

## Injector pulse width = DID 0x1208 (locked)

Operator graphed "Inj pulse-b1" and did 3 throttle blips. Broadcast RPM
(`0x1F9`) gave the blip windows independently (idle 759 → 2344 / 3309 /
2703 rpm). `0x1208` (2-byte) was the only DID whose value traced the
reported ms across all four points:

| | idle | blip 1 | blip 2 | blip 3 |
|---|---|---|---|---|
| NT510 readout | 2.14 | ~4 | ~9 | ~9.4 ms |
| `0x1208` raw | 4962 | 10384 | 23487 | 24416 |
| scaled | 1.9 | 4.0 | 9.05 | 9.4 | (LSQ err 0.28) |

Triple-validated: NT510 wire-truth + independent broadcast-RPM timing +
4-state cold-enrichment (`0x1208` cold 2.68 ms > warm 2.17 ≈ NT510 2.14).
Supersedes the earlier `0x1209` guess (a correlated sibling). **Scale ≈
`raw × 4e-4` ms (~raw/2400); exact constant still to be calibrated** (the
operator's eyeballed blip peaks are approximate; idle 2.14 is the firm
anchor). Identification is firm; `0x1206`/`0x1207` are correlated
fuel/pressure siblings.

## Access + constraints (baked into tooling)

- ECM refuses `22` with `7F 22 80` in the default session; positive only
  after **`10 C0`** (sub-functions `0x81`/`0x85` open but don't unlock
  0x22; `0xC0` does). `3E 00` TesterPresent is rejected → keep alive by
  re-sending `10 C0` every ~2 s (S3 ≈ a few s).
- **Session `0xC0` ⊥ standard OBD Mode 01** — the ECM stops answering
  Mode 01 while a non-default session is held. Read-only / no actuation;
  broadcast sniffing unaffected. Engine-behavior side-effects of `0xC0`
  still uncharacterized — parked A/B owed before in-motion DID polling.
- Now in code: `CanObdClient.enter_diagnostic_session`,
  `CanableMode22Transport(session=0xC0, keepalive_seconds=2.0)`,
  `scan_constant_dids.py --session C0`, and an early-return on negative
  response so a full sweep is minutes not hours.
