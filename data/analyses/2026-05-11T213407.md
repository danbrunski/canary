2. **Plausibility verification of high-confidence bindings.** Coolant continues

   state remains stable, no unexpected zero-runs anywhere. This is exactly
   the kind of "background validation" that decoded sessions are supposed to

3. **Confirmation that the recorder works in normal close-out conditions.**
   3-minute capture with no errors, clean SIGINT stop — the same hardness
   improvements that protect against drive-time disconnects also work for
   normal use.

## What would have made this richer

This was an untagged restart capture; not the intended use of the tagging
pipeline. For the data to feed back into the bindings/IF training loop, even
two tags at the start and end of the trip would have been enough to define
"the whole session is one driving window" for windowed analysis.

Backfill is easy if you remember roughly when you started moving:

```bash
# Already at desk; recording was 3:13 long
.venv/bin/python scripts/tag.py drive_start \
    --session data/sessions/2026-05-11T213407 \
    --offset 5s

.venv/bin/python scripts/tag.py drive_end \
    --session data/sessions/2026-05-11T213407 \
    --offset 3m05s
```

That would let `tools/broadcast_signals.py` operate on this session too.

## No new bindings derived

Without tags there's no per-window differential to run. The session
supplements existing bindings rather than discovering new ones.
