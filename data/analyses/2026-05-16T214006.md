# Session 2026-05-16T214006 — Mode 22 DID breakthrough (Nissan session 0xC0)

**Purpose:** first successful Canable-native Mode 22 (UDS ReadDataByIdentifier)
capture on the Xterra. Established how to reach the Nissan DID space, then a
4-state protocol (KOEO → cold idle → warm idle → ~2500 rpm) to split
live signals from calibration constants and ground-truth a few. This is the
Phase 4.E enabler (injector-PW / timing / fuel-surface targets live here).

## Hardware / state

- Canable `/dev/ttyACM0`, slcan 500 kbps, on the OBD-II port. Re-attached via
  usbipd after a drop. Request-only (UDS 0x22 / 0x10); no recorder running.
- Engine arc: KOEO → cold idle (Mode 01: RPM 762, coolant 61 °C) → warm idle
  (coolant ~92 °C) → held ~2500 rpm in park (~15 s), then off.

## The access breakthrough

A blind `--canable` sweep of 0x0000–0x1FFF on 7E0 returned **0 DIDs** —
because **service 0x22 is gated behind a Nissan diagnostic session**:

- `22 XXXX` cold → `7F 22 80` (serviceNotSupportedInActiveSession). The ECM
  *is* UDS-capable; 0x22 is just session-locked.
- Standard `10 03` (extended session) → `7F 10 12` (subFunctionNotSupported).
- Session sub-function sweep `10 01..C0`: **`10 81`, `10 85`, `10 C0` return
  positive `50 xx`**. Only **`0x C0`** unlocks 0x22 (`22 1101` → `62 11 01 63`).
- `3E 00` TesterPresent is rejected even in-session (`7F 3E 12`), so the
  session is kept alive by **re-sending `10 C0` every ~2 s** (S3 ≈ a few s;
  a ~6 s gap drops it — verified). This worked across a 165 s sweep.

### ⚠ Session 0xC0 is mutually exclusive with OBD Mode 01

Proven (T1): with no session, Mode 01 works (RPM `0BEA`, coolant `7A`).
*While in `0xC0`*, Mode 01 functional `0x7DF` gets **no response** and
physical `7E0 01 0C` is actively refused (`7F 01 80`); DIDs work. Let the
session lapse → Mode 01 returns, DIDs go back to `7F 22 80`. So:

- It is **read-only / no actuation** (only 0x10 + 0x22 sent) — engine not
  commanded; broadcast frames keep flowing (passive sniffing unaffected).
- But you **cannot hold `0xC0` for DID polling and run active Mode 01 at the
  same time**. A live monitor must **time-slice** (lapse `0xC0` → Mode 01 →
  re-enter) or choose. Anything else on the OBD port expecting Mode 01 goes
  dark while `0xC0` is held.
- Engine-behavior side-effects of `0xC0` (idle/timing/adaptation, MIL) are
  **not yet characterized** — the parked in-session-vs-out A/B is still owed
  before any in-motion DID polling.

## 4-state capture (138 DIDs answered, 0x1100–0x12FF in session 0xC0)

Snapshots in `data/sessions/2026-05-16T214006/` (gitignored):
`dids_koeo_c0.json`, `dids_idle_c0.json` (cold), `dids_idle_warm_c0.json`,
`dids_rev2500_c0.json`, plus `groundtruth_cold_idle.json`.

Classification across the 4 states:

- **87 constant across all 4** → calibration / config DIDs.
- **3** KOEO-only flags (engine-state).
- **12** warmup-driven (changed cold→warm idle, flat idle↔rev).
- **~36** load/RPM-driven (moved warm-idle→rev) — the live-signal pool.

### Ground-truth-validated identifications

| DID | Signal | Basis |
|---|---|---|
| `0x1219` | **Engine RPM**, raw ≈ rpm | 0 KOEO; cold fast-idle 1190; warm idle 756 (Mode 01 = 762 ✓); rev 2418 (~2500 ✓). Ratio 3.20 ≈ RPM ratio. |
| `0x1101` | **Coolant temp**, `A−40` | KOEO 59 °C; cold **61 °C** (Mode 01 = 61 ✓); warm 90 °C; rev 97 °C. |
| `0x1209` | **Injector PW / MAF** (top candidate) | Cold-enriched (676 cold > 359 warm) AND RPM-driven (359→984 rev) — the fuel/air signature. The Phase 4.E injector-PW target. |
| `0x1206`/`0x1207` | MAP / intake-pressure pair | ~1020 KOEO (≈atmospheric) → ~220 running → lower at rev (manifold vacuum). |
| `0x120D`–`0x1210` | timing / per-bank cluster | +~50 idle→rev (advance off-idle). |
| `0x1107`–`0x110A`,`0x113C` | coherent 5-DID group | identical: 0 off / 93 idle / 70 rev — per-cylinder-ish; targeted RE next. |
| `0x1201` | RPM-correlated (load/torque?) | 0 KOEO; warm 60 → rev 193 (ratio 3.22, tracks RPM, small magnitude). |

4-byte values at block boundaries (`0x1100/1120/1140/1160/1200/1220/1240`)
look like supported-DID bitmasks (Mode-01-style block headers).
